# Заметки по работе с Git: VS Code vs Терминал

## 3 удобные вещи в VS Code

1. **Визуальный просмотр изменений (Diff).**
   Очень удобно видеть изменения в файлах бок о бок (side-by-side) прямо в редакторе. Сразу видно, какие строки были добавлены, изменены или удалены, не нужно использовать `git diff` и читать вывод в консоли.

2. **Индексация отдельных строк (Staging hunks).**
   В панели Source Control можно легко выбрать и добавить в коммит не весь файл целиком, а только конкретные измененные строки (или блоки). Это позволяет делать более атомарные и чистые коммиты без использования `git add -p`.

3. **Разрешение конфликтов слияния (Merge Conflict Resolver).**
   Встроенный интерфейс для разрешения конфликтов. VS Code подсвечивает конфликтующие области и предлагает кнопки «Accept Current Change», «Accept Incoming Change» или «Accept Both», что гораздо быстрее и безопаснее, чем вручную искать маркеры `<<<<<<<` в терминале.

## 1 вещь, которую удобнее делать в терминале

1. **Сложные манипуляции с историей (Interactive Rebase и Reflog).**
   Такие команды, как `git rebase -i HEAD~3` (для сквоша, редактирования или удаления коммитов) или восстановление потерянных коммитов через `git reflog`, гораздо быстрее и прозрачнее выполняются именно в терминале. Ввод текстовых команд и просмотр полного лога в консоли дает больше контроля над сложными операциями, чем графический интерфейс IDE.
